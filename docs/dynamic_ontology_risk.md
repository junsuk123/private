# 온톨로지 시장 분석과 동적 리스크 정책

2026-09-20 추가 개편. 기존 전략의 낮은 성과를 단순히 매수 제한을 풀어 해결하지 않는다. 전략 성과를 시장·국면·버전·실거래/가상 관측으로 분리하고, 검증된 시장 관측에서 진입과 청산에 사용하는 수치 정책을 생성한다. 이 변경은 실거래 수익률 개선을 입증한 결과가 아니다.

## 실제 실행 연결

`web._build_realtime_trading_engine()`에서 `OntologyPolicyRuntime` 하나를 생성한다. 같은 resolver를 `TradePlanBuilder`, `StrategySessionManager`, `SharedLiveDecisionEngine`, `RealtimeTradingEngine`에 전달한다. 실제 리스크 매니저에는 `ontology_policy_required=True`를 설정한다.

1. 시장별 ContextRuntime의 국면·신뢰도·시장 폭·방향과, 검증된 출처 관계가 있는 국제 지표를 읽는다.
2. 해당 종목·시장·세션·스트림의 **완료된 연속 1분봉**에서 최소 5개 수익률을 계산한다. 분산의 시간 단위를 60초로 기록하며, 틱 변동성을 분 변동성으로 바꾸어 표시하지 않는다.
3. 실제 양방향 호가와 거래량에서 스프레드·유동성·호가 경과 시간을 계산한다. 원래 거래소 시각과 수신 시각을 유지한다. 새 평가 시각으로 오래된 시세를 갱신하지 않는다.
4. 진입 당시 입력·온톨로지 정책과 이후 가상 체결 결과가 연결되고 시장별 검증을 통과한 시간 인식 R-GCN은 불확실성·예상 순손실을 보조 근거로 제공한다. 이 근거는 시장 관측만으로 생성한 정책보다 손실 한도·노출을 늘릴 수 없다. 진입 시 동결한 가상 청산과 실시간으로 조정되는 실제 청산은 구별하며, 가상 수익 예측으로 실거래 권한을 부여하지 않는다. 기존 분봉 라벨은 연구용 학습에만 사용한다.
5. 비용 엔진의 왕복 수수료·세금·슬리피지 추정과 관측을 결합해 수치 정책을 생성한다. 누락·미래·상충·다른 시장의 필수 근거는 신규 진입을 허용하지 않는다. 선택적 지표 하나의 누락이 정상적인 필수 근거 전체를 무효화하지는 않는다.
6. 정책에 맞는 순수익 여유·위험 대비 보상·수량·현금·업종 노출을 만족할 때만 계획을 동결한다. 주문 직전에는 현재 정책과 실제 계좌로 다시 확인하며, 동결 수량을 늘리지 않는다.

판단 루프에서는 RDF 추론 엔진, 브로커 추가 호출, 모델 학습을 실행하지 않는다. 관측 배열과 작은 수치 계산을 사용하고 분봉 캐시는 최대 256종목·종목당 64개로 제한한다. RDF 생성은 별도의 읽기 전용 감사 요청에서 실행한다.

새 전방 가상 평가 저널의 기본 경로도 기기별 `runtime_database_path("directional-shadow.sqlite3")`를 사용한다. Synology 폴더에서 실행하면 활성 SQLite 파일이 동기화 폴더 밖에 위치한다. 기존 프로젝트 저널은 삭제·자동 이전하지 않으며, 명시적인 `DIRECTIONAL_SHADOW_STORE_PATH` 설정은 유지된다. 기존 전략 성과 이력은 별도 성과 저장소에서 계속 읽는다.

## 동적으로 생성되는 값

| 용도 | 생성되는 값 | 주요 입력 |
| --- | --- | --- |
| 진입 경제성 | 비용 차감 순수익 하한, 목표 수익률, 최소 보상/위험 비율, 비용 대비 예상 수익 비율 | 비용, 시간 단위가 명시된 변동성, 스프레드, 국면, 불확실성 |
| 자금 배분 | 종목·업종 비중, 거래당 손실 예산, 일일 손실 예산, 현금 유보율, 일일 거래 횟수 | 시장, 스트레스, 관측 품질, 신뢰도, 비용 |
| 시세와 체결 | 허용 호가 경과 시간, 스프레드, 진입 가격 범위, 슬리피지 제한 | 양방향 호가, 유동성, 시장 잡음, 비용 |
| 포지션 관리 | 연성 손절, 강제 손절, 긴급 손절, 추적 손절, 이익 보호 개시점·반납 비율 | 변동성, 비용, 스트레스, 유동성 |
| 조기 탈출 | 최소 관찰 시간, 서로 다른 관측의 확인 횟수, 국면 변화 확률, 온톨로지 악화 강도, 음의 예측 기준 | 시장 잡음, 국면 신뢰도, 불확실성, 스트레스 |
| 시간과 재진입 | 최대 보유 시간, 재진입 대기 시간 | 원래 전략 시간 범위, 추세, 스트레스, 거래 비용 |

수식 계수는 공개된 연구 초기값이며 과거 수익률에 최적화되었다는 주장이 아니다. 거래 비용과 변화하는 기대 수익을 함께 고려하는 방향은 [Gârleanu·Pedersen 연구](https://www.nber.org/papers/w15205)와 부합하지만, 그 논문의 최적해를 구현했다는 의미는 아니다.

`config/ontology_risk_policy.yaml`의 값은 운영 임계치를 고정하는 값이 아니라 **상한**이다. 기본 상한은 일일 손실 1%, 거래당 손실 0.2%, 국장 종목 비중 15%, 미장 12%, 강제 손절 2%, 긴급 손절 3.5%다. 실제 생성되는 값은 시장 근거에 따라 더 작아진다. 가격 급변이나 체결 지연으로 실제 손실이 이 값을 초과할 수 있다.

현금·매도 가능 수량·환율 환산·상품 권한·운영자 자본 보호선은 별도의 실제 계좌 제약이다. 신경망 점수로 해제하지 않는다. 기존 환경변수의 손실 제한은 상한을 더 낮출 수 있으며, 시장에서 생성된 손절값을 큰 고정값으로 바꾸지는 못한다.

## 청산과 성과 처리의 변경

- 새 운영 경로에서는 `20원`이나 `$0.05` 같은 고정 절대 금액이 익절을 결정하지 않는다. 통화에 독립적인 비용 차감 수익률과 잡음 구간을 사용한다.
- 손실 매도를 막던 소액 계좌·일반 손실 매도 설정은 새 동적 강제 청산 경로를 막지 않는다. 신규 매수용 일일 횟수·유동성·성과 조건으로 기존 포지션 청산을 거부하지 않는다.
- 포지션을 보유한 뒤에는 새 정책이 기존 손절 장벽이나 최대 보유 시간을 넓힐 수 없다. 근거가 끊겼으면 마지막 유효 장벽과 안전 상한을 유지한다. 정책을 재평가할 때 원래 전략 시간 범위를 보존해 매번 보유 시간이 재귀적으로 줄어드는 현상도 방지한다.
- 조기 탈출 확인은 서로 다른 관측 시각만 센다. 같은 캐시를 빠르게 여러 번 읽어 확인 횟수를 채우지 않는다. 비정상 가격에서 조기 청산 신호를 만들지 않는다.
- 동결 주문 수량을 부동소수점 오차로 1주 줄이지 않도록 정수 경계의 표현 오차만 보정한다. 실제 비용·현금·최종 비중 검증은 유지한다. 매도 가능 수량 `0`을 보유 수량으로 덮어쓰지 않는다.
- 주문 제출 시점의 지정가는 체결이나 실현 손익이 아니다. 새 경로에서는 제출 기록으로 손실 성과와 24시간 재진입 금지를 만들지 않는다. 실제/가상 전략 성과는 [성과 적응 모듈](strategy_performance_adaptation.md)에서 별도로 다룬다.

기존 저수준 생성자의 resolver 기본값은 이전 재현·오프라인 API와의 호환을 위해 `None`이다. 실제 웹 런타임 팩토리는 필수 정책을 주입한다. 이 차이는 통합 테스트로 검증한다.

## 형식과 화면

온톨로지는 [정식 스키마 문서](formal_policy_ontology.md)에 설명한 **Class / Instance / Object Property / Data Property / Axiom**을 사용한다. OWL의 의미와 SHACL의 완전성 검증을 분리한다. 시장·세션·종목·관측·국면·전략·위험 평가·정책·임계치를 연결하며, 감사 그래프에는 R-GCN의 실제 전략 관계도 포함한다.

`/account`는 현재 정책의 시장·종목, 순수익 목표, 손절·추적 손절, 보유 시간, 비중·일일 손실 예산, 근거 출처, 유효 시각과 진입 불가 이유를 표시한다.

- `/api/ontology/policy`: 캐시된 정책과 근거
- `/api/ontology/policy/schema`: OWL Turtle 스키마
- `/api/ontology/policy/{KR|US}/{symbol}`: 해당 종목의 근거·정책·전략 관계 RDF

## 확인한 범위와 남은 성과 검증

최종 검증 범위는 [검증 기록](validation/ontology_refactor_2026-09-21.md)에 정리했다.

미래/오래된/잘못된 시장의 자료, 분봉 시간 구간, 검증되지 않은 모델, 정책 만료, 정수 수량, 환율과 일일 예산, 고정 수익 하한의 잔존, 청산 차단, 손절 완화, 확인 횟수, 보유 시간 재계산 등을 회귀 테스트한다. 그래프 모델의 구조 선택과 실제 NPU 측정은 [별도 문서](temporal_relational_graph_model.md)를 참조한다.

운영 DB의 과거 관측은 일부 출처가 검증되지 않았고 실거래 순수익을 입증하기에 부족하다. 이번 작업에서는 브로커 주문을 제출하거나 운영 모델을 수익 검증 없이 승격하지 않았다. 충분한 실제 시세·비용 차감 결과와 시장별 시간 순서 검증이 있어야 모델과 전략의 진입 권한을 얻는다. 현재 설계상 근거가 부족하거나 수익 전망이 음수이면 거래 대기가 정상적인 결과다.

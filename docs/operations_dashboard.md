# 운영 대시보드

`/account`는 계좌 손익 → 국내·미국 시장 → 거래 대기 사유 → 보유 종목·실제 추론 장치 → 주문·체결 순서로 표시합니다. 기존 차트, 3D 그래프, 학습 진단과 터미널 배치는 `/account/advanced`에서 이용할 수 있습니다.

## 읽기 경로

- `GET /api/operations/overview`: 캐시된 시장·엔진·실행 진단을 한 응답으로 정리합니다.
- `GET /api/account/summary`: 저장된 실계좌 스냅샷만 읽습니다. 대시보드를 열거나 새로고침해도 계좌 REST 조회나 주문을 호출하지 않습니다.
- 화면이 보일 때만 5초 간격으로 확인하고, 한 번의 요청이 끝난 뒤 다음 요청을 예약합니다. 각 요청은 8초 제한이 있습니다. 일부 API에 문제가 생겨도 다른 패널은 갱신합니다.

`app.operations_dashboard.build_operations_overview()`는 외부 I/O가 없는 변환 함수입니다. `create_account_router(operations_provider=...)`로 서버 내부 관측값을 공급합니다. 함수의 `markets`에는 `KR`와 `US`를 독립된 키로 전달합니다. 각 시장의 `phase`, `allows_new_entry`, `regime`, `source`, `quote_age_seconds`, `healthy_symbols`, `strategy_ids`가 화면에 표시됩니다. `trading`은 기존 실시간 거래 상태, `blockade`는 기존 진입 진단 체인 형식입니다.

## 표시 원칙

확인되지 않은 잔고·손익은 `—`이며, 확인된 0원과 구분합니다. 마지막 계좌 확인 시각이 120초 이상 오래되거나 미래로 어긋나면 마지막 확인값으로 표시하고 `authoritative=false`로 반환합니다. 연결 지연이 생기면 기존 값을 유지하되 현재 상태로 오인하지 않도록 표시합니다.

국내·미국 시장이 모두 거래 가능해도 계좌의 실행 주체는 하나라는 사실을 표시합니다. 시장 개장, 전략 신호, 주문 권한, 주문 접수와 실제 체결은 서로 다른 상태입니다. 진입 진단은 최초 미충족 조건을 강조하고 이후 단계에서 독립적으로 확인된 결과도 보존합니다.

장치 표시는 요청한 NPU와 실제 실행 장치를 구분합니다. NPU를 사용할 수 없어 CPU로 실행 중이면 CPU와 대체 사유를 표시합니다. 모델 이름이나 버전만으로 학습 완료나 수익성을 추정하지 않습니다.

## 검증

`tests/test_operations_dashboard.py`는 동시에 열린 두 시장, 최초 차단 조건, 실계좌 캐시 만료, 기존 터미널 경로, 실제 JavaScript 렌더 함수와 부분 통신 실패를 외부 요청 없이 검증합니다.
